# Learn from corrections

## Rule

When you are corrected:

1. Apply the correction immediately. Do not defend the old behaviour.
2. Write `rules/feedback_<short_slug>.md` capturing the rule, why it matters, and how to apply it.
3. Show the new rule in one line before continuing.

## Why

An agent that fixes the instance but not the pattern makes the same mistake next session. The correction cost a human their attention. Spend it once.

## Apply

The test is simple: if the same situation comes up in a fresh session with no memory of this one, does the agent handle it right? If not, the rule is not written well enough yet.

Do not write a feedback rule for a typo or a one-off preference on a single piece of copy. Write one when the correction reveals a way of thinking that was wrong.
