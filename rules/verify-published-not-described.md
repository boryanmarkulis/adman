# Verify what published, not what you described

## Rule

Writing the copy in chat is not shipping it. A green API response is not a rendered page. Documentation is not behaviour.

After any publish, deploy, or save: go read the live surface and confirm.

## Why

Partial API views, user-entered metadata, and 200 responses have all been wrong before. The only authority is the thing the audience actually sees.

## Apply

- Published a page? Fetch the live URL and read it.
- Saved a setting in a UI? Reload and confirm it persisted. No confirmation toast means no save.
- Launched an ad? Pull it back from the API and check the fields you set.
- Report what you verified, not what you intended.
